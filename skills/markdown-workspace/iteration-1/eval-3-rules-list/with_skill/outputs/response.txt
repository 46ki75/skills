# Common markdownlint Rules Reference

Below is a comprehensive list of important markdownlint rules you should be
aware of when writing Markdown documents.

---

## Heading Rules

**MD001 - Heading levels should only increment by one level at a time**
Headings must go H1 → H2 → H3, not jump from H1 directly to H3.
Example fix: Don't use `### Section` immediately after `# Title`.

**MD018 - No space after hash on atx style heading**
There must be a space after the `#` character(s) in headings.
Bad:  `##Heading`
Good: `## Heading`

**MD022 - Headings should be surrounded by blank lines**
Add a blank line before and after every heading.

**MD023 - Headings must start at the beginning of the line**
No leading spaces before heading markers.

**MD024 - Multiple headings with the same content**
Avoid duplicate heading text (unless in different sections — configurable).

**MD025 - Multiple top-level headings in the same document**
A document should have only one H1 (`#`) heading as its title.

**MD036 - Emphasis used instead of a heading**
Don't use `**bold**` or `_italic_` as a substitute for a real heading.
Bad:  `**Section Title**`
Good: `## Section Title`

**MD041 - First line in a file should be a top-level heading**
Documents should start with an H1 heading.

---

## List Rules

**MD004 - Unordered list style**
Use a consistent marker (`-`, `*`, or `+`) throughout a document.

**MD005 - Inconsistent indentation for list items at the same level**
All items at the same nesting level must have the same indentation.

**MD007 - Unordered list indentation**
List items should be indented with a consistent number of spaces (default: 2).

**MD029 - Ordered list item prefix**
Ordered list items should use `1.` (ordered) or sequential numbers consistently.

**MD030 - Spaces after list markers**
There should be exactly one space after list markers (`-`, `*`, `1.`).

**MD032 - Lists should be surrounded by blank lines**
Add blank lines before and after list blocks for clarity.

---

## Whitespace Rules

**MD009 - Trailing spaces**
No trailing whitespace at the end of lines (except intentional line breaks).

**MD010 - Hard tabs**
Use spaces, not tab characters, for indentation.

**MD012 - Multiple consecutive blank lines**
No more than one consecutive blank line (configurable).

**MD047 - Files should end with a single newline character**
Every file should end with exactly one newline.

---

## Line Length

**MD013 - Line length**
Lines should not exceed 80 characters (configurable). URLs are typically exempt.
Config examples:
  - `"MD013": false`                        — disable entirely
  - `"MD013": { "line_length": 120 }`       — raise limit
  - `"MD013": { "code_blocks": false }`     — exclude code blocks

---

## Code Block Rules

**MD031 - Fenced code blocks should be surrounded by blank lines**
Add blank lines before and after fenced code blocks (``` or ~~~).

**MD040 - Fenced code blocks should have a language specified**
Always specify a language after the opening fence for syntax highlighting.
Bad:  ` ``` `
Good: ` ```bash `

**MD046 - Code block style**
Use a consistent style (fenced vs. indented) throughout a document.

---

## Link & URL Rules

**MD034 - Bare URL used**
Wrap bare URLs in angle brackets or use proper Markdown link syntax.
Bad:  `https://example.com`
Good: `<https://example.com>` or `[Example](https://example.com)`

**MD039 - Spaces inside link text**
No leading/trailing spaces inside link text brackets.
Bad:  `[ link text ](url)`
Good: `[link text](url)`

**MD042 - No empty links**
Links must have a non-empty URL.

---

## Emphasis & Inline Rules

**MD037 - Spaces inside emphasis markers**
No leading/trailing spaces inside emphasis markers.
Bad:  `* emphasized *`
Good: `*emphasized*`

**MD038 - Spaces inside code span elements**
No leading/trailing spaces inside backtick spans.
Bad:  `` ` code ` ``
Good: `` `code` ``

---

## HTML & Special Content

**MD033 - Inline HTML**
Raw HTML is disallowed by default. Disable with `"MD033": false` if needed.

**MD011 - Reversed link syntax**
Catch accidentally reversed link syntax: `(text)[url]` vs `[text](url)`.

---

## Document Structure

**MD019 - Multiple spaces after hash on atx style heading**
Only one space after `#` characters.

**MD026 - Trailing punctuation in heading**
Headings should not end with `.`, `,`, `;`, `:`, `!`, or `?`.

**MD028 - Blank line inside blockquote**
Avoid blank lines inside blockquotes — they may cause rendering issues.

**MD045 - Images should have alternate text**
Always provide alt text in image syntax: `![alt text](image.png)`.

## Tips

- Run `markdownlint-cli2 --fix file.md` to auto-fix ~70–90% of issues.
- Rules marked "No" in the auto-fixable column require manual intervention.
- Use a `.markdownlint.json` config to disable or adjust rules per project.
- Full documentation: https://github.com/DavidAnson/markdownlint/blob/main/doc/Rules.md
