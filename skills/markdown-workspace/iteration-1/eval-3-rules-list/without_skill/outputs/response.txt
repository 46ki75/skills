# Comprehensive List of Important Markdownlint Rules

Markdownlint enforces consistent Markdown style and prevents common errors.
Below is a comprehensive list of important rules grouped by category.

---

## Headings

- **MD001** – Heading levels should only increment by one level at a time.
  Bad: # H1 followed by ### H3 (skips H2).

- **MD002** – First heading should be a top-level heading (h1). (Deprecated in newer versions; replaced by MD041.)

- **MD003** – Heading style should be consistent (atx `#`, atx_closed `# #`, or setext `===`/`---`).

- **MD018** – No space after hash on atx style heading.
  Bad: `#Heading`  Good: `# Heading`

- **MD019** – Multiple spaces after hash on atx style heading.
  Bad: `#  Heading`  Good: `# Heading`

- **MD020** – No space inside hashes on closed atx style heading.
  Bad: `#Heading#`  Good: `# Heading #`

- **MD021** – Multiple spaces inside hashes on closed atx style heading.

- **MD022** – Headings should be surrounded by blank lines.

- **MD023** – Headings must start at the beginning of the line (no indentation).

- **MD024** – Multiple headings with the same content (duplicate headings).

- **MD025** – Multiple top-level headings in the same document.

- **MD026** – Trailing punctuation in headings (e.g., trailing period or colon).

- **MD041** – First line in file should be a top-level heading.

---

## Lists

- **MD004** – Unordered list style should be consistent (dash `-`, asterisk `*`, or plus `+`).

- **MD005** – Inconsistent indentation for list items at the same level.

- **MD006** – Consider starting bulleted lists at the beginning of the line. (Deprecated.)

- **MD007** – Unordered list indentation. Default: 2 spaces per level.

- **MD029** – Ordered list item prefix. Options: `one` (all `1.`), `ordered` (1. 2. 3.).

- **MD030** – Spaces after list markers. Consistent spacing after `-`, `*`, `+`, or `1.`.

- **MD032** – Lists should be surrounded by blank lines.

---

## Whitespace and Blank Lines

- **MD009** – Trailing spaces (except intentional line breaks with 2+ spaces).

- **MD010** – Hard tabs (should use spaces instead).

- **MD012** – Multiple consecutive blank lines (default max: 1).

- **MD047** – Files should end with a single newline character.

---

## Line Length

- **MD013** – Line length. Default max: 80 characters (configurable; headings, code blocks, and tables can be excluded).

---

## Code Blocks and Inline Code

- **MD014** – Dollar signs used before commands without showing output (use them only when showing output alongside input).

- **MD031** – Fenced code blocks should be surrounded by blank lines.

- **MD035** – Horizontal rule style should be consistent (`---`, `***`, `___`).

- **MD040** – Fenced code blocks should have a language specified.
  Bad: \`\`\`  Good: \`\`\`python

- **MD046** – Code block style should be consistent (fenced vs. indented).

- **MD048** – Code fence style should be consistent (backticks `` ` `` vs. tildes `~`).

---

## Links and Images

- **MD011** – Reversed link syntax. Bad: `(link)[url]`  Good: `[link](url)`

- **MD034** – Bare URL used without angle brackets or link syntax.
  Bad: `http://example.com`  Good: `<http://example.com>` or `[text](url)`

- **MD039** – Spaces inside link text. Bad: `[ link ](url)`  Good: `[link](url)`

- **MD042** – No empty links. Bad: `[text]()`

- **MD045** – Images should have alternative text (alt text).
  Bad: `![](image.png)`  Good: `![description](image.png)`

---

## Emphasis and Bold

- **MD036** – Emphasis used instead of a heading. Using `**text**` or `*text*` as a standalone paragraph instead of a proper heading.

- **MD049** – Emphasis style should be consistent (asterisks `*` vs. underscores `_`).

- **MD050** – Strong/bold style should be consistent (asterisks `**` vs. underscores `__`).

---

## HTML

- **MD033** – Inline HTML. Raw HTML tags in Markdown (configurable to allow specific tags).

---

## Blockquotes

- **MD027** – Multiple spaces after blockquote symbol.
  Bad: `>  text`  Good: `> text`

- **MD028** – Blank line inside blockquote.

---

## Horizontal Rules

- **MD035** – Horizontal rule style should be consistent.

---

## Tables (GFM Extension)

- **MD055** – Table pipe style should be consistent (leading/trailing pipes).

- **MD056** – Table column count should be consistent (all rows same number of columns).

---

## Document Structure and Metadata

- **MD041** – First line in file should be a top-level heading (h1).

- **MD043** – Required heading structure. Allows enforcement of a specific heading hierarchy.

- **MD044** – Proper names should have the correct capitalization (configurable list).

---

## Miscellaneous

- **MD037** – Spaces inside emphasis markers.
  Bad: `* text *`  Good: `*text*`

- **MD038** – Spaces inside code span elements.
  Bad: `` ` code ` ``  Good: `` `code` ``

---

| MD012 | No multiple consecutive blank lines              |
| MD013 | Line length limit                                |
| MD022 | Headings surrounded by blank lines               |

| MD032 | Lists surrounded by blank lines                  |

| MD040 | Fenced code blocks have language specified       |

---

These rules are based on the markdownlint project (https://github.com/DavidAnson/markdownlint)
and its associated rule documentation. Rules can be enabled, disabled, or configured
via a `.markdownlint.json`, `.markdownlint.yaml`, or `.markdownlint.jsonc` configuration file.
