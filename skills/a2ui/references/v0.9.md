# A2UI v0.9 — Draft Specification Reference

> Version 0.9 is currently in draft status. For production use, consider v0.8 (Stable).
> Designed to be embedded directly in an LLM's system prompt (prompt-first / in-context schema).

## Design philosophy

- **Prompt-first** — the schema is embedded in the system prompt; the LLM generates JSON guided by examples and rules rather than strict structured output
- **Flat adjacency list** — same as v0.8: a flat component list with ID references
- **Simplified JSON** — native JSON types replace verbose wrapper objects (plain string instead of `{"literalString":"..."}`, plain object instead of array of key-value pairs)
- **Unified catalog** — components and functions live in a single `basic_catalog.json`
- **Modular schemas**: `common_types.json` · `server_to_client.json` · `basic_catalog.json`
- **Progressive rendering** — rendering begins as soon as the `root` component is available; no explicit "render now" signal needed

## Server-to-client message types

Every message must include `"version": "v0.9"` and contain exactly one of: `createSurface`, `updateComponents`, `updateDataModel`, `deleteSurface`.

### `createSurface`

Must be sent **before** any other message for a surface. Signals the client to allocate the surface and prepare for rendering.

```json
{
  "version": "v0.9",
  "createSurface": {
    "surfaceId": "user_profile_card",
    "catalogId": "https://a2ui.org/specification/v0_9/basic_catalog.json",
    "theme": {
      "primaryColor": "#00BFFF"
    },
    "sendDataModel": true
  }
}
```

- `surfaceId` (string, required): Unique ID for the surface.
- `catalogId` (string, required): URI identifying which catalog of components / functions to use. Use `https://a2ui.org/specification/v0_9/basic_catalog.json` for the standard catalog.
- `theme` (object, optional): Theme parameters defined in the catalog (e.g. `primaryColor`).
- `sendDataModel` (boolean, optional, default `false`): When `true`, the client includes the full data model in the metadata of every message it sends back to the server.

> Sending `createSurface` for a `surfaceId` that already exists is an error. Delete it first with `deleteSurface`.

### `updateComponents`

Adds or updates a flat list of UI components in a surface. Can be sent multiple times to stream the UI progressively or to update it after user actions.

```json
{
  "version": "v0.9",
  "updateComponents": {
    "surfaceId": "user_profile_card",
    "components": [
      {
        "id": "root",
        "component": "Column",
        "children": ["user_name", "user_title"]
      },
      {
        "id": "user_name",
        "component": "Text",
        "text": "John Doe"
      },
      {
        "id": "user_title",
        "component": "Text",
        "text": "Software Engineer"
      }
    ]
  }
}
```

- `surfaceId` (string, required): Target surface (must already be created).
- `components` (array, required): Flat list of component objects. Each object:
  - `id` (string, required): Unique within the surface. **Must have exactly one component with `id: "root"`.**
  - `component` (string, required): Component type name from the catalog (e.g. `"Text"`, `"Button"`).
  - Additional properties as defined by the catalog for that component type.

### `updateDataModel`

Updates a value in the surface's data model. Uses JSON Pointer paths and plain JSON values — no typed wrappers.

```json
{
  "version": "v0.9",
  "updateDataModel": {
    "surfaceId": "user_profile_card",
    "path": "/user/name",
    "value": "Jane Doe"
  }
}
```

```json
{
  "version": "v0.9",
  "updateDataModel": {
    "surfaceId": "user_profile_card",
    "path": "/contact",
    "value": {
      "firstName": "John",
      "lastName": "Doe",
      "email": "john@example.com"
    }
  }
}
```

- `surfaceId` (string, required): Target surface.
- `path` (string, optional): JSON Pointer. Defaults to `/` (replaces the entire data model).
- `value` (any, optional): New value at `path`. Omit or set to `null` to remove the key.

### `deleteSurface`

Removes a surface and all associated components and data.

```json
{
  "version": "v0.9",
  "deleteSurface": {
    "surfaceId": "user_profile_card"
  }
}
```

## Component model

### Component object structure

```json
{
  "id": "my_button",
  "component": "Button",
  "child": "btn_label",
  "variant": "primary",
  "action": {
    "event": {
      "name": "submit_form",
      "context": {
        "formId": "f-123",
        "userInput": { "path": "/form/input" }
      }
    }
  }
}
```

The `component` field is a **string discriminator** (the type name). All other properties are the component's own fields, defined by the catalog. This flat structure is much easier for LLMs to generate than v0.8's key-wrapper approach.

### Data binding

Any string property can receive either a plain literal or a binding object:

```json
"text": "Hello, World!"              // literal
"text": { "path": "/user/name" }     // data model binding
```

For numbers and booleans:

```json
"checked": true
"checked": { "path": "/prefs/darkMode" }
```

#### String interpolation with `formatString`

Use the `formatString` function to mix literals and bindings in a single string. The `${...}` syntax is **only** valid inside `formatString` arguments:

```json
{
  "id": "greeting",
  "component": "Text",
  "text": {
    "call": "formatString",
    "args": {
      "format": "Hello, ${/user/firstName} ${/user/lastName}!"
    }
  }
}
```

Nested function calls are supported:

```json
{
  "call": "formatString",
  "args": {
    "format": "Created: ${formatDate(value: ${/createdAt}, format: 'MMM d, yyyy')}"
  }
}
```

### Container children

```json
{ "children": ["child_a", "child_b"] }
```

For dynamic lists (template):

```json
{
  "id": "list_container",
  "component": "Column",
  "children": {
    "path": "/items",
    "componentId": "item_template"
  }
}
```

- Plain array — static ordered list of child IDs
- Object with `path` + `componentId` — dynamic list rendered from the data model

#### Scope in templates

Inside a template item, **relative paths** (not starting with `/`) resolve against the current item:

```json
{ "path": "name" }    // → /items/0/name for first item
{ "path": "/company" } // → always root-level /company
```

### Actions

#### Server action (sends event to agent)

```json
{
  "action": {
    "event": {
      "name": "submit_form",
      "context": {
        "userId": "u-42",
        "inputValue": { "path": "/form/input" }
      }
    }
  }
}
```

#### Local (client-side) action

```json
{
  "action": {
    "functionCall": {
      "call": "openUrl",
      "args": {
        "url": { "path": "/link/href" }
      }
    }
  }
}
```

## Standard component catalog (basic_catalog)

| Component | Key properties | Notes |
|-----------|---------------|-------|
| `Text` | `text` (DynamicString), `variant` (`h1`…`h6`, `body`, `caption`, …) | Display text |
| `Button` | `child` (ComponentId), `variant` (`primary`, `secondary`, …), `action` | Triggers action |
| `Row` | `children` (array or template), `justify`, `align` | Horizontal layout |
| `Column` | `children` (array or template), `justify`, `align`, `weight` | Vertical layout |
| `Card` | `child` (ComponentId) | Elevated container |
| `Image` | `url` (DynamicString) | Image display |
| `Icon` | `name` (string) | Material icon name |
| `TextField` | `label`, `value` (DynamicString), `variant` (`shortText`, `longText`), `checks` | Text input with validation |
| `CheckBox` | `label`, `value` (DynamicBoolean) | Boolean toggle |
| `ChoicePicker` | `variant` (`mutuallyExclusive` \| `multiSelect`), `options` (array of `{label, value}`), `value` (DynamicStringList) | Selection |
| `Divider` | `axis` (`horizontal` \| `vertical`) | Visual separator |

### Validation functions (for `checks` on `TextField`)

| Function | Arguments | Description |
|----------|-----------|-------------|
| `required` | `value` | Field must not be empty |
| `email` | `value` | Must be a valid email address |
| `regex` | `value`, `pattern` | Must match the regex pattern |
| `minLength` | `value`, `min` | Minimum character count |
| `maxLength` | `value`, `max` | Maximum character count |

### Client-side functions (for `action.functionCall` and expressions)

| Function | Arguments | Description |
|----------|-----------|-------------|
| `openUrl` | `url` | Open a URL in the browser |
| `formatDate` | `value`, `format` | Format a date/timestamp string |
| `formatString` | `format` | String interpolation with `${...}` |

## Client capabilities (metadata)

Sent in every A2A message from client to server:

```json
{
  "metadata": {
    "a2uiClientCapabilities": {
      "supportedCatalogIds": [
        "https://a2ui.org/specification/v0_9/basic_catalog.json"
      ]
    }
  }
}
```

When `sendDataModel` is `true` on the surface, the client also includes:

```json
{
  "metadata": {
    "a2uiClientDataModel": {
      "surfaceId": "contact_form_1",
      "dataModel": { "contact": { "firstName": "John", "email": "john@example.com" } }
    }
  }
}
```

## Tips for generating v0.9 JSON

1. **Always send `createSurface` first** — it initialises the surface; all other messages depend on it.
2. **The `root` component triggers rendering** — include it in your first `updateComponents` message to start rendering as early as possible.
3. **Use plain JSON types** — `"text": "Hello"` not `"text": {"literalString":"Hello"}`. `"value": {"path":"/x"}` for bindings.
4. **Data model updates use plain objects** — `"value": {"name": "Alice", "age": 30}` not an adjacency-list array.
5. **String interpolation only inside `formatString`** — don't use `${...}` in regular string properties.
6. **Catalog URI is required** — always include `catalogId` in `createSurface`; use `https://a2ui.org/specification/v0_9/basic_catalog.json` for the standard catalog.
7. **Every message needs `"version": "v0.9"`** — include it on every line in the stream.
8. **To update after a user action** — send `updateComponents` and/or `updateDataModel`; no need to resend `createSurface`.
