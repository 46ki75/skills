# A2UI v0.8 — Stable Specification Reference

> Version 0.8 is the current stable release, recommended for production use.
> Optimised for LLMs that support structured output / function calling.

## Design philosophy

- **Structured-output first** — every message is designed to be generated by an LLM in strict JSON mode or via function calling
- **Flat adjacency list** — components are a flat list; parent–child relationships are expressed via string ID references
- **Separation of structure and state** — `surfaceUpdate` messages define the component tree; `dataModelUpdate` messages provide the live data
- **Progressive rendering** — clients buffer incoming components and render only after receiving `beginRendering`

---

## Server-to-client message types

Every line in the JSONL stream is one of these four message types.

### `surfaceUpdate`

Adds or updates components in a surface. Send as many of these as needed before `beginRendering`; they can also arrive after `beginRendering` to update the live UI.

```json
{
  "surfaceUpdate": {
    "surfaceId": "my_surface",
    "components": [
      {
        "id": "unique-component-id",
        "component": {
          "Text": {
            "text": { "literalString": "Hello" }
          }
        }
      }
    ]
  }
}
```

- `surfaceId` (string, optional): Defaults to a single implicit surface when omitted.
- `components` (array, required): Flat list of component objects. Each object:
  - `id` (string, required): Unique within the surface.
  - `component` (object, required): Exactly one key whose name is the component type (e.g. `"Text"`, `"Button"`). The value is the component's properties.

### `dataModelUpdate`

Upserts data into a surface's data model.

```json
{
  "dataModelUpdate": {
    "surfaceId": "my_surface",
    "path": "user",
    "contents": [
      { "key": "name",       "valueString": "Alice" },
      { "key": "age",        "valueNumber": 30 },
      { "key": "isVerified", "valueBoolean": true },
      {
        "key": "address",
        "valueMap": [
          { "key": "street", "valueString": "1 Main St" },
          { "key": "city",   "valueString": "Anytown" }
        ]
      }
    ]
  }
}
```

- `surfaceId` (string): Target surface.
- `path` (string, optional): JSON Pointer path within the data model. Omit to update the root.
- `contents` (array): Adjacency-list of typed entries. Each entry has `key` and exactly one of:
  - `valueString` — string value
  - `valueNumber` — numeric value
  - `valueBoolean` — boolean value
  - `valueMap` — nested map (recursive `contents` array)

### `beginRendering`

Signals the client to start rendering the surface. Send this **after** all initial `surfaceUpdate` and `dataModelUpdate` messages.

```json
{
  "beginRendering": {
    "surfaceId": "my_surface",
    "root": "root",
    "catalogId": "https://a2ui.org/specification/v0_8/standard_catalog_definition.json",
    "styles": {
      "primaryColor": "#007bff"
    }
  }
}
```

- `surfaceId` (string): Target surface.
- `root` (string, required): The `id` of the root component to start rendering from.
- `catalogId` (string, optional): Catalog URI. Defaults to `https://a2ui.org/specification/v0_8/standard_catalog_definition.json`.
- `styles` (object, optional): Theme tokens such as `primaryColor`.

### `deleteSurface`

Removes a surface and all its components/data.

```json
{
  "deleteSurface": {
    "surfaceId": "my_surface"
  }
}
```

## Component model

### Component type wrapper

On the wire each component object contains exactly one key for the type:

```json
{
  "id": "my_button",
  "component": {
    "Button": {
      "child": "btn_label",
      "action": { "name": "submit_form" }
    }
  }
}
```

### BoundValue — data binding

Any property that accepts dynamic data uses a `BoundValue` object:

```json
{ "literalString": "Static text" }
{ "path": "/user/name" }
{ "path": "/user/name", "literalString": "Guest" }
```

- `literalString` / `literalNumber` / `literalBoolean` / `literalArray` — static value
- `path` — JSON Pointer into the surface's data model; resolved at render time
- Both together — initialises the data model at `path` with the literal value, then binds to `path` (shorthand for initialisation)

### Container children

Containers (`Row`, `Column`, `List`) use a `children` object with **exactly one** of:

```json
{ "children": { "explicitList": ["child_a", "child_b"] } }
```

```json
{
  "children": {
    "template": {
      "dataBinding": { "path": "/items" },
      "componentId": "item_template"
    }
  }
}
```

- `explicitList` — static ordered array of child component IDs
- `template` — dynamic list: iterates over the array at `dataBinding.path`, rendering `componentId` for each item; inside the template, relative data paths resolve against the current item

## Standard component catalog

| Component | Key properties | Notes |
|-----------|---------------|-------|
| `Text` | `text` (BoundValue), `usageHint` (`h1`…`h6`, `body`, `caption`, …) | Display text |
| `Button` | `child` (ComponentId), `action.name`, `action.context` | Triggers `userAction` |
| `Row` | `children`, `alignment`, `crossAxisAlignment` | Horizontal layout |
| `Column` | `children`, `alignment`, `crossAxisAlignment` | Vertical layout |
| `Card` | `child` (ComponentId) | Elevated container |
| `Image` | `url` (BoundValue) | Displays an image |
| `List` | `children` | Scrollable list |
| `TextField` | `label`, `value` (BoundValue), `hint` | Text input |
| `Checkbox` | `label`, `value` (BoundValue) | Boolean toggle |
| `Divider` | `axis` (`horizontal` \| `vertical`) | Visual separator |
| `Icon` | `name` | Material icon name |

## Catalog negotiation

**Client capabilities** (sent in every A2A message metadata):

```json
{
  "metadata": {
    "a2uiClientCapabilities": {
      "supportedCatalogIds": [
        "https://a2ui.org/specification/v0_8/standard_catalog_definition.json"
      ],
      "inlineCatalogs": []
    }
  }
}
```

**Server agent card snippet**:

```json
{
  "capabilities": {
    "extensions": [
      {
        "uri": "https://a2ui.org/a2a-extension/a2ui/v0.8",
        "params": {
          "supportedCatalogIds": [
            "https://a2ui.org/specification/v0_8/standard_catalog_definition.json"
          ],
          "acceptsInlineCatalogs": true
        }
      }
    ]
  }
}
```

## Client-to-server messages

### `userAction`

Sent when the user interacts with a component that has an `action`.

```json
{
  "userAction": {
    "name": "submit_form",
    "surfaceId": "my_surface",
    "sourceComponentId": "submit_btn",
    "timestamp": "2025-09-19T17:05:00Z",
    "context": {
      "userInput": "resolved value from data model",
      "formId": "f-123"
    }
  }
}
```

The client resolves all `BoundValue`s in the component's `action.context` before sending.

### `error`

Sent when the client encounters a rendering or binding error. Payload is flexible.

```jsonl
{"surfaceUpdate":{"components":[{"id":"root","component":{"Column":{"children":{"explicitList":["profile_card"]}}}}]}}
{"surfaceUpdate":{"components":[{"id":"profile_card","component":{"Card":{"child":"card_content"}}}]}}
{"surfaceUpdate":{"components":[{"id":"card_content","component":{"Column":{"children":{"explicitList":["header_row","bio_text"]}}}}]}}
{"surfaceUpdate":{"components":[{"id":"header_row","component":{"Row":{"alignment":"center","children":{"explicitList":["avatar","name_column"]}}}}]}}
{"surfaceUpdate":{"components":[{"id":"avatar","component":{"Image":{"url":{"literalString":"https://example.com/profile.jpg"}}}}]}}
{"surfaceUpdate":{"components":[{"id":"name_column","component":{"Column":{"alignment":"start","children":{"explicitList":["name_text","handle_text"]}}}}]}}
{"surfaceUpdate":{"components":[{"id":"name_text","component":{"Text":{"usageHint":"h3","text":{"literalString":"A2UI Fan"}}}}]}}

{"dataModelUpdate":{"contents":{}}}
{"beginRendering":{"root":"root"}}
```

## Tips for generating v0.8 JSON

1. **Output one component per `surfaceUpdate` line** to stream progressively — the client can start buffering immediately.
2. **Always send `beginRendering` last** in the initial burst; the client waits for it before the first render.
3. Use `explicitList` for known children and `template` when iterating over a data-bound list.
4. When using `path` + `literal*` together on a `BoundValue`, the client both initialises the data model and binds to it in one step — convenient for setting defaults.
5. The `surfaceId` field is optional on all messages when there is only one surface; omit it to keep the stream compact.
6. To update the UI after a `userAction`, send new `surfaceUpdate` / `dataModelUpdate` messages on the existing SSE stream — no need for another `beginRendering`.
